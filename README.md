# Projectra

Командный таск-менеджер (по типу YouGile): доски с перетягиванием задач,
встроенный мессенджер, календарь сроков, визуальные связи задач, общая и
личная работа. Регистрация пользователей — только администратором.

## Возможности

- **Доски** — общие (видны всем) и личные (владелец + приглашённые), колонки,
  задачи с приоритетом, сроками, исполнителями и цветом.
- **Свободная раскладка досок** — на десктопе карточки досок можно разложить по
  холсту как удобно (позиции сохраняются персонально); на мобильном — обычная
  адаптивная сетка.
- **Приоритеты** — 5 уровней (Не срочный · Низкий · Средний · Высокий ·
  Критичный), каждый со своим цветом.
- **Статусы задач** — управляются администратором (`/admin/statuses`: название +
  цвет, свои можно добавлять/удалять). Гибридная модель: статус по умолчанию
  берётся из колонки, но заданный вручную закрепляется и не сбивается переносом.
- **Rich-text в описании** — форматирование по типу Markdown (жирный, курсив,
  подчёркнутый, зачёркнутый, моноширинный) с предпросмотром.
- **Повторение задач** — день/неделя/месяц/год, будни-пресет, предпросмотр
  ближайших дат; при выполнении срок переносится на следующий цикл.
- **Часовые пояса** — время сроков показывается в поясе смотрящего (по умолчанию
  Иркутск), задаётся в профиле.
- **Drag & Drop** — перетягивание задач между колонками и колонок между собой;
  на мобильных — долгое нажатие.
- **Личные задачи** — видны только создателю (и тем, у кого есть право
  «видеть чужие личные задачи»).
- **Мессенджер** — личные диалоги и чаты досок, счётчики непрочитанных,
  всплывающие уведомления.
- **ИИ-помощник Cerebras / Gemini / Groq** — всплывающий чат из левого меню: читает доступные
  пользователю доски и задачи, помогает с описаниями и от имени текущего
  аккаунта может создавать и редактировать задачи, назначать исполнителей,
  добавлять комментарии, менять сроки/статусы, перемещать и отмечать выполнение.
  Описания и комментарии поддерживают Markdown, а в чате отображаются реальные
  этапы выполняемых действий. История хранится в PostgreSQL отдельно для
  каждого аккаунта. Cerebras используется первым, при его ошибке или исчерпании
  лимита запрос автоматически переходит к Gemini, затем к Groq, если его ключ задан.
- **Календарь** — задачи по срокам, перенос дедлайна перетягиванием.
- **Связи задач** — канвас на React Flow (связь / блокирует / зависит).
- **Real-time** — изменения досок и сообщения приходят мгновенно (SSE).
- **Гибкие права** — гранулярная система прав по группам (доски, задачи,
  комментарии, сообщения, экспорт, расширенный доступ, администрирование);
  права настраиваются по ролям и по конкретным пользователям (`/admin/permissions`).
  Есть «god-mode» права для админа: видеть все доски/чужие личные задачи, читать
  любые переписки, управлять любой доской.
- **Админка** — пользователи (создание/блокировка/роли/сброс пароля/**фото под
  отдельным правом**), права, шаблоны досок, статусы, расширенная **аналитика**
  (статусы/приоритеты/по доскам/загрузка), журнал действий.

> Подзадачи, учёт времени и метки временно скрыты за фиче-флагами
> (`src/lib/features.ts`) — включаются одним флагом.

## Стек

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind 4 · Prisma 6 +
**PostgreSQL** · сессии на JWT (jose) + bcrypt · dnd-kit · @xyflow/react ·
motion · **Docker Compose**.

## Запуск (разработка)

БД — PostgreSQL (поднимается через docker compose), приложение — локально.

```bash
docker compose up -d db     # поднять Postgres (localhost:5432)
npm install
cp .env.example .env         # заполните AUTH_SECRET (POSTGRES_* уже заданы)
npx prisma db push           # применить схему к БД
npm run db:seed              # создать администратора (идемпотентно)
npm run dev                  # http://localhost:3000
```

Сервер слушает `0.0.0.0`, поэтому открывается и по локальному IP
(`http://<ip-машины>:3000`) — LAN-адреса машины уже разрешены в
`next.config.ts` (`allowedDevOrigins`).

**Администратор по умолчанию** (из сид-скрипта): логин `v.smolin`,
пароль `Qq123456`. Пароль меняется в профиле; новых пользователей заводит
администратор.

## Продакшен (Docker Compose)

Весь стек (Postgres + приложение) поднимается одной командой:

```bash
docker compose up -d --build
docker compose exec app npm run db:seed   # первый раз, если нужны демо-данные
# → http://localhost:3000
```

Схема применяется автоматически при старте контейнера (`prisma db push` в
`docker-entrypoint.sh`). Подробности, переезд с SQLite без потери данных и
пошаговая инструкция для Ubuntu — в **[DOCKER.md](./DOCKER.md)**.

Переменные окружения (`.env` / `.env.example`):

- `DATABASE_URL` — строка подключения PostgreSQL (host-side: `localhost`,
  внутри compose: `db`).
- `AUTH_SECRET` — длинная случайная строка для подписи сессий.
- `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` — параметры контейнера БД.
- `CEREBRAS_API_KEY` / `GEMINI_API_KEY` / `GROQ_API_KEY` — серверные ключи
  провайдеров; в браузер не передаются. Достаточно одного ключа.
- `PROJECTRA_AI_PROVIDER` — основной провайдер: `cerebras` (по умолчанию),
  `gemini` или `groq`; остальные настроенные провайдеры используются как fallback.
- `PROJECTRA_AI_PROXY_URL` — общий необязательный HTTP(S)-прокси. Отдельный
  прокси можно задать через `CEREBRAS_PROXY_URL`, `GEMINI_PROXY_URL` или
  `GROQ_PROXY_URL`.
- `PROJECTRA_AI_HISTORY_MESSAGES`, `PROJECTRA_AI_MAX_COMPLETION_TOKENS`,
  `PROJECTRA_AI_MAX_TOOL_ROUNDS` — размер контекста и ограничения агентской цепочки.

> **Важно:** real-time (доски, чат, уведомления) построен на in-memory
> шине событий + SSE, поэтому приложение должно работать **одним
> экземпляром** Node-процесса (не в serverless и не за несколькими
> репликами без общего брокера). За обратным прокси (nginx/Caddy) нужна
> поддержка потоковых ответов (`proxy_buffering off;` для `text/event-stream`).

## Полезные команды

- `npm run db:push` — применить схему Prisma к БД.
- `npm run db:seed` — создать администратора (идемпотентно).
- `npm run lint` — проверка ESLint.
- `node --experimental-sqlite --import tsx scripts/migrate-sqlite-to-postgres.ts`
  — перенос данных из старой SQLite-базы в PostgreSQL (см. DOCKER.md).
